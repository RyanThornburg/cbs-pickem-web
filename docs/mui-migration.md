# Moving off MUI

Work happens on the `mui-migration` branch. Pushes to `main` deploy, so the
branch merges only once a whole step is done and verified. The goal is that
every page looks the same as before, pixel for pixel, while MUI and Emotion
leave the bundle.

## Decisions (user, 2026-10-18)

- **Interactive pieces: [Base UI](https://base-ui.com)** (`@base-ui/react`,
  pinned exactly; stay a release behind, at least two weeks old). It's from
  the MUI team, so Tooltip, Popover, Select, Tabs, ToggleGroup and Menu swap
  close to 1:1, and its Tooltip opens on touch.
- **Styling: CSS modules**: a `Name.module.css` next to each component, built
  into Vite, no new tooling. Colors and sizes come from `src/styles/tokens.css`.
- Why: MUI's family is about a third of the JavaScript (below), plus the
  repeated fights with it (the theme's orange Alert, the touch-only Tooltip
  behind `BadgeTooltip`, overriding the desktop Tabs' roles and focus) and
  the forced upgrades (6 → 7 → 9). It isn't the fix for tap speed: that was
  re-rendering (see CLAUDE.md, "Keep tab switches cheap").

## Baseline (main at `ce4c548`)

## How to convert a component

1. **Look first, measure, don't assume MUI's defaults.** MUI 9 differs from
   what older docs say: it has no letter spacing on buttons or text (computed
   `normal`, not `0.02857em`). When a value is unclear, measure the element's
   computed style and box in the current build.
2. **Markup:** plain elements. `Box`/`Stack` become `div`s (or the right
   element), `Typography` becomes `p`/`span`/`h*` with the font set in CSS
   (body text is `var(--text-md)`, line height 1.43; captions 12px, 1.66).
3. **Styles:** a `Name.module.css` next to the component, one class per
   element, with the codebase's habit of a short comment saying why. Theme
   spacing is 8px a step (`p: 2` is 16px) and `borderRadius: 2` is 16px
   (2 × the theme's 8px). Breakpoints are written out: `sm` 600px, `md`
   900px, `lg` 1200px; `up("md")` is `(min-width: 900px)`, `down("md")` is
   `(max-width: 899.95px)`.
4. **Shared pieces** live in `src/dashboard/ui/`: `Button`, `Icon`,
   `SegmentedControl`, and `ui.module.css` (`visuallyHidden`). Add one there
   only when a second component needs it; otherwise keep CSS local. Their
   CSS sits in `@layer ui`, so a component's own (unlayered) module always
   overrides them, whatever order the stylesheets load in: pass a
   `className` and write the override plainly. A responsive override from a
   parent still on MUI becomes a prop with its own class (`DetailsToggle`'s
   `fullWidthOnPhone`), since inline `style` can't hold a media query.
5. **Icons:** `<Icon name="InfoOutlined" />` (`size` small/medium/large/
   inherit, `label` for a meaningful one). Shapes come from
   `ui/iconData.ts`, generated by `node scripts/gen-icons.mjs`: run it after
   importing a new MUI icon, before converting the file that uses it. Once
   MUI is gone, new icons are added by hand from Material Symbols.
6. **A converted component takes `className` or `style`, never `sx`.** A
   parent still on MUI passes one-off spacing as `style={{ marginTop: 16 }}`
   until the parent is converted too, then it moves into the parent's module.
7. **Before converting, grep the parents for MUI class selectors**
   (`"& .MuiButton-root"`, `"&.Mui-selected"`, …). They silently stop
   matching the new element: the Team page's band turned its back link
   white that way, and the swap left it grey until `BackLink` got
   `inheritColor`.
8. **Keep behavior:** roles, labels, `aria-*`, keyboard. Base UI's
   ToggleGroup moves between segments with arrow keys and has one tab stop;
   that change is accepted.
9. **Memoized tabs stay memoized** with stable props (CLAUDE.md).

## Checking a step

```sh
npm run build
node scripts/visual/snap.mjs --out .visual/after      # needs .visual/main
node scripts/visual/diff.mjs .visual/main .visual/after
```

- `.visual/` is gitignored: `fixtures.json` holds recorded prod API answers
  (with real names; never commit it). `--record` re-records everything;
  `--record-missing --pages <name>` fetches only what a new page needs and
  keeps the rest, so the baseline stays valid. A recording run's own shots
  come from slow live fetches and can be incomplete, so always re-shoot
  `.visual/main` afterwards from a `main` build (`.visual/dist-main`: `git
  worktree add`, symlink `node_modules`, `vite build --outDir`; then
  `snap.mjs --dist .visual/dist-main --out .visual/main`).
- Admin pages use made-up data (`scripts/visual/adminFixtures.mjs`): the
  real admin routes sit behind Access and carry emails.
- It shoots 19 pages at 360px and 1280px (`PAGES` in `snap.mjs`: every tab,
  a past week, team and player pages, no player selected, a failed
  leaderboard, a failed app shell, an open box score with player stats, and
  both Admin views) with a frozen clock, reduced motion and no transitions.
  `--pages a,b` shoots only those. Add a page when a converted piece isn't
  on any of them.
- **SMALL** (under 0.1% of a page) can be text or sub-pixel jitter: open the
  diff image (`.visual/diff/`). Known case: the recap strip's controls on
  `picks-error@1280` shift by a sub-pixel (identical measured boxes); MUI's
  desktop tab underline can be a pixel wider at each end (4 px, seen on
  `main` against itself). Two shots of the same build can also differ by a
  few words' rasterization.
- MUI's measuring components can race the screenshot: Records' table
  switcher at 360 once showed its scroll arrow (CHANGED, 0.11%) and matched
  on four re-shoots. Re-shoot a page before chasing a diff in something the
  step didn't touch.
- **CHANGED** is a real difference until shown otherwise. Compare the
  computed styles of the element in both builds.
- `node scripts/visual/clickthrough.mjs` clicks through every converted
  control at 360 and 1280 (switches by tap and arrow keys, box score groups,
  the Key popover, the team back link, a User Picks row, Admin's form).
- `SeasonRecapCharts` can measure its width late right after load (on
  `main` too), so a fresh season shot can draw the charts at another scale:
  re-shoot before chasing it.
- Then `npm run lint`, `npm run format:check`, `npm run test:all` (not while
  Playwright is running: worker start-up timeouts skip test files).
